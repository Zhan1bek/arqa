# AGENTS.md

Инструкции для ИИ-агентов (Codex, Claude Code и др.) и людей. Здесь собраны **правила
проекта**; требования лежат в [docs/SPEC.md](docs/SPEC.md), решения — в [docs/adr/](docs/adr/).
Если правило здесь расходится с ADR, прав ADR, а этот файл нужно исправить.

## Проект

Дневник смен водителя такси: сервер отдаёт поездки и сводку за день, мобильное приложение
их показывает и добавляет новые.

```
packages/core   доменная логика без I/O: схема поездки, сводка, даты, деньги (+ тесты)
apps/server     Fastify 5 + node:sqlite: HTTP API, идемпотентная запись (+ тесты через inject)
apps/mobile     Expo / React Native: экран дня, форма поездки, API-клиент с повторами
data/           демо-данные, сервер загружает их при старте (идемпотентно)
docs/           SPEC.md (критерии приёмки AC-*), adr/ (решения), AI_WORKFLOW.md
```

## Команды

```bash
npm install            # один раз, из корня (npm workspaces)
npm run dev:server     # API на http://localhost:3000
npm run dev:web        # приложение в браузере; dev:mobile — Expo Go на телефоне
npm test               # все тесты (vitest)
npm run check          # формат + линт + типы + тесты — то же, что в CI
```

Node ≥ 22.13 (нужен встроенный `node:sqlite`). Зависимости ставить только из корня.
В `apps/mobile` пакеты ставятся через `npx expo install <pkg>`, а не `npm install`.

## Инварианты домена — не нарушать

1. **Деньги — целые тенге.** Никаких float, `toFixed`, `parseFloat` для сумм. Формат вывода —
   только `formatTenge` из core. → [ADR-0001](docs/adr/0001-money-as-integers.md)
2. **День считается в часовом поясе водителя, а не в UTC.** Запрещено определять дату через
   `toISOString().slice(0, 10)` или `getDate()` на сервере. Дата поездки — `localDateOf(start, tz)`
   из core. → [ADR-0002](docs/adr/0002-day-boundary.md)
3. **Запись поездки идемпотентна по `id`.** Уникальность обеспечивает БД (`PRIMARY KEY` +
   `ON CONFLICT DO NOTHING`), а не «SELECT, потом INSERT». Тот же id с другими данными → 409,
   никогда не перезапись. → [ADR-0003](docs/adr/0003-idempotency.md)
4. **Правила валидации живут только в `packages/core`.** Сервер и клиент импортируют одну схему;
   дублировать проверки в обработчиках или формах нельзя.

## Как вносить изменения

1. Найди или добавь критерий в `docs/SPEC.md`. Если меняется поведение, сначала обнови спеку.
2. Сначала тест, потом код. В названии теста пиши id критерия: `it('AC-6: ...')`.
3. Минимальный дифф: без попутного рефакторинга и без новых зависимостей без причины
   (если зависимость нужна, объясни её в описании коммита).
4. `npm run check` должен быть зелёным, прежде чем сказать «готово».
5. Коммиты — Conventional Commits (`feat(server): ...`, `fix(core): ...`, `test: ...`).

## Где агенту нельзя доверять себе

- **API библиотек.** Версии тут свежие: Zod 4, Fastify 5, Vitest 5, Expo SDK 57. Сверяйся с
  `node_modules/<pkg>/package.json` и типами, а не с памятью. Для Expo — см. `apps/mobile/AGENTS.md`.
- **Даты и часовые пояса.** Любую новую логику с датами проверяй тестом на поездку 00:00–05:00
  по Алматы: по UTC это предыдущий день.
- **Тесты.** Нельзя ослаблять или удалять тест, чтобы он прошёл. Если тест кажется неверным,
  остановись и опиши почему.
- **«Работает».** Это утверждение только после запуска: тесты, `curl` к API или скриншот приложения.

- [ ] Инварианты 1–4 соблюдены (их проверяет сабагент `reviewer`)
