# Как проект делался с ИИ

Проект целиком сделан в **Claude Code**. Ниже описано, как была устроена работа, кто что
делал и, главное, **где ИИ ошибся и как это поймали**. Каждый пункт можно проверить по
истории коммитов.

## Процесс

```
SPEC (AC-1…10) + ADR ──► AGENTS.md / CLAUDE.md ──► контракт модулей
        │
        ├──► test-writer ×2 (фон): тесты core и API только по SPEC, не видя кода
        └──► основная сессия: реализация core и server
                     │
                     ▼
            test-writer (фон): тесты клиентской логики │ основная сессия: UI
                     │
                     ▼
     reviewer + api-qa в свежем контексте (параллельно) ──► исправления ──► E2E (Playwright)
```

1. **Сначала спецификация, потом код.** Требования задания переписаны в проверяемые
   критерии [SPEC.md](SPEC.md); решения по опасным местам (деньги, часовой пояс,
   идемпотентность) зафиксированы в [ADR](adr/) до первой строки кода.
2. **Правила для агентов** лежат в [AGENTS.md](../AGENTS.md): инварианты домена, команды,
   Definition of Done и раздел «где агенту нельзя доверять себе». Этот формат читают и
   Codex, и Claude Code; [CLAUDE.md](../CLAUDE.md) подключает его и добавляет только
   специфику Claude. У мобильного приложения свой вложенный `AGENTS.md`.
3. **Тесты пишет не автор кода.** Сабагент `test-writer` получал только SPEC и сигнатуры
   функций, а реализацию писала основная сессия параллельно. Поэтому тесты проверяют
   спецификацию, а не подстраиваются под код.
4. **Ревью в свежем контексте.** `reviewer` не видел, как писался код, и не верил
   комментариям. Каждую находку он подтверждал конкретным входом через пробный скрипт.
   `api-qa` проверял живой сервер через curl, а не код.
5. **Автоматика:** хук форматирует каждый изменённый агентом файл, скилл `/verify` и CI
   запускают одну и ту же проверку (`npm run check`), а смоук в CI поднимает настоящий
   сервер.
6. **«Работает» — только после запуска.** Финальный сценарий прогнан в браузере через
   Playwright ([e2e/screenshots.py](../e2e/screenshots.py)), включая обрыв связи при сохранении.

## Что проверялось руками, а не принималось на веру

- **Поведение библиотек на свежих версиях** (Zod 4, Fastify 5, Expo SDK 57). Проверялось в
  REPL и по `.d.ts`, а не по памяти модели. Например, `Date.parse('2026-02-30T08:00:00+05:00')`
  в V8 молча возвращает 2 марта, а `z.iso.datetime` такую дату отвергает. Поэтому
  несуществующие даты отсекает схема, а не `Date`.
- **Шаблон Expo** принёс свой `AGENTS.md` с указанием «использовать Expo Router». Для
  приложения из одного экрана это лишнее, поэтому инструкция переписана: устаревшая
  инструкция для агента так же вредна, как устаревшая документация.
- **Цифры примера из задания** сверяются тестом, смоуком в CI и E2E: 3 900 / −585 / 3 315.

## Честные оговорки

- Красной фазы TDD фактически не было: тесты и реализация писались параллельно, поэтому
  тесты впервые запустились уже против кода. Независимость тестов это сохранило: агент не
  видел реализацию. Но то, что тесты падают без кода, отдельно не проверялось.
- Самую серьёзную ошибку (п. 1) не поймал ни один из 226 тестов, нашло только ревью. Тесты
  проверяют то, что записано в спеке, а п. 1 в спеке не было. Теперь он там есть (AC-9).
- Codex в этом проекте не запускался; `AGENTS.md` написан так, чтобы работать с ним
  без изменений.
