# Спецификация: дневник смен водителя

Источник: тестовое задание <https://jobs.arqa.cc/>. Ниже — требования, переписанные в проверяемые
критерии приёмки (AC). Каждый AC закрыт тестом; id критерия указан в названии теста,
поэтому покрытие ищется так: `grep -rn "AC-6" packages apps`.

## Модель данных

Поездка (`Trip`):

| поле         | тип                   | правила                                                                               |
| ------------ | --------------------- | ------------------------------------------------------------------------------------- |
| `id`         | string                | 1–64 символа `[A-Za-z0-9_-]`, генерирует клиент                                       |
| `start`      | ISO 8601 со смещением | `2026-10-01T08:10:00+05:00`; без смещения — ошибка; точность — секунда; год 2000–2100 |
| `end`        | ISO 8601 со смещением | строго позже `start`                                                                  |
| `amount`     | целое число тенге     | `0 < amount ≤ 10 000 000`                                                             |
| `payment`    | `"cash"` \| `"card"`  |                                                                                       |
| `commission` | целое число тенге     | `0 ≤ commission ≤ amount`                                                             |

## Критерии приёмки

### Сводка и список за день

- **AC-1.** `GET /api/days/:date` (`date` = `YYYY-MM-DD`) возвращает поездки за этот день,
  отсортированные по времени начала.
- **AC-2.** Там же — сводка: число поездок, выручка (сумма `amount`), комиссия, «на руки»
  (`выручка − комиссия`), разбивка выручки на наличные и карту. Для примера из задания:
  2 поездки, 3 900 ₸, комиссия 585 ₸, на руки 3 315 ₸, наличные/карта 1 500 / 2 400.
- **AC-3.** «День» — календарный день в часовом поясе водителя (по умолчанию `Asia/Almaty`),
  а не в UTC. Поездка относится к дню своего **начала**: поездка 23:50–00:20 попадает
  в день, когда началась. Подробности — [ADR-0002](adr/0002-day-boundary.md).
- **AC-4.** День без поездок — это нулевая сводка и пустой список, а не 404.
  Некорректная дата (`2026-13-01`, `2026-02-30`, `yesterday`) → `400`.

### Добавление поездки

- **AC-5.** `POST /api/trips` валидирует тело по таблице выше; при ошибке → `400` с
  перечнем полей и понятными сообщениями. Битый JSON → `400`.
- **AC-6.** Повторная отправка той же поездки (тот же `id`, те же данные) не создаёт дубль:
  первый запрос → `201`, повторы → `200` с той же поездкой. Это верно и для одновременных
  запросов, и после перезапуска сервера. «Те же данные» сравниваются по смыслу:
  `08:10+05:00` и `03:10Z` — одно и то же время.
- **AC-7.** Тот же `id` с **другими** данными → `409 Conflict`, существующая запись не
  меняется (молча перезаписывать деньги нельзя). Подробности — [ADR-0003](adr/0003-idempotency.md).

### Клиент

- **AC-8.** Приложение показывает сводку и список поездок за день, позволяет листать дни.
- **AC-9.** Из приложения можно добавить поездку; клиент проверяет форму той же схемой,
  что и сервер, а повтор после сетевой ошибки уходит с тем же `id` **и теми же данными**:
  если исход отправки неизвестен, поля формы блокируются до повтора (иначе правка суммы
  под тем же id даёт 409, а «новая форма» — дубль). Ответ `200` без своей поездки
  (например, страница входа в Wi-Fi) успехом не считается.

### Качество

- **AC-10.** Тесты на расчёт сводки (AC-2, AC-3) и на защиту от дублей (AC-6, AC-7);
  `npm run check` (формат, линт, типы, тесты) зелёный в CI.

## Вне рамок

Авторизация и несколько водителей, редактирование и удаление поездок, офлайн-очередь
на клиенте, поездки через полночь в форме приложения (API их принимает).
